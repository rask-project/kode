Remote folders over SSH: edit a project on another machine as if it were
here. A beta: try it and tell us what breaks.

## Remote folders (SSH)

- **File ▸ Connect to Server… (⇧⌘K).** A host from `~/.ssh/config`, or
  `user@host`. Kode installs a small agent on the host the first time
  (`~/.cache/kode/remote`; Linux x86_64 and arm64, macOS), checks it on
  every connection and replaces it when Kode changes. Passwords,
  passphrases and unknown host keys are asked in Kode.
- **The host's folder in the sidebar**, followed as it changes there; new
  file and folder, rename, duplicate, paste, Move to Trash, all on the host.
  **Find File (⌘K)** searches the host.
- **Documents read and saved through the agent**: each save is atomic and
  checked against the version you opened; a file changed on the host
  meanwhile asks first ("changed on disk", Keep Mine).
- **Language servers run on the host**: clangd (with the project's
  compilation database), qmlls (with its build folder), pyright and the
  others, found on the host's login PATH or in folders you add. Problems,
  completion, Go to Definition and quick fixes as with local files.
- **A dropped connection comes back by itself**, the folders listed and
  the language servers started again.
- **Open Recent** keeps remote files and folders; `kode ssh://host/path`
  opens one from a terminal.

## Settings ▸ Remote

- Your hosts, each one's connection and Kode's agent.
- **Sign in with a key**: Kode tells whether the host takes this Mac's key,
  and Install Key adds it (making one when you have none), so no password
  is asked again.
- **Language servers on the host**: folders searched before its PATH (a
  clangd or qmlls outside it, e.g. from a Qt under `/opt`), the host's PATH,
  and each language's server found there.

## Fixes

- Closing a window could crash Kode (Find File's blur kept the window
  captured).
- A custom language server added in Settings nested the ones before it.
