Large files without waiting, and a roomier find bar.

## Large files

- **Large files open in the background.** From 2 MB on, the file is read and
  decoded off the main thread: the window says "Opening…" and stays
  responsive, and a 100 MB file blocks it for 0.1 ms instead of about
  230 ms.
- **A jump far down a large file is colored at once.** The lines in view are
  highlighted from a guess until the highlighting from the top gets there:
  the end of a 100 MB file takes 7 ms to color instead of 22 s.
- **Opening takes less memory.** UTF-8 is decoded as it is read, and the
  file is no longer decoded twice to find its encoding: opening 100 MB
  peaks at 495 MB instead of 782 MB.

## Changes

- **Re-indent on save re-indents only the lines edited** since the last
  save, as VS Code's "format modifications only": saving no longer
  rewrites a whole file's indentation, and it no longer waits on large
  files (a minute at 100 MB before, 19 ms now after editing a line).
  Edit > Re-Indent (⌃I) still re-indents the selection.
- **The find bar has more room.** The Find and Replace fields line up and
  take the width the buttons leave, and Replace and All fill the space
  under the buttons. The match count is a badge on the Find field's corner,
  so nothing moves as it changes.
- **Open, Open Folder and Save As start in your home folder** instead of
  the root of the disk.

## Memory

With a 100 MB C++ file open and highlighted, Kode uses about 500 MB; VS Code
1.148 uses 1.2 GB with highlighting off, and Xcode 27.2 uses 3.2 GB. The
numbers and how they were measured are in `docs/editor-bench.md`.
